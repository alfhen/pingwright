There's a new sheriff in tag town.

In Anglo-Saxon England, a reeve was the official who kept order for the king. The reeve of a whole county was the shire reeve. Say it fast for a few hundred years and you get sheriff.

Tagreeve does the same job for your tags. It walks the beat as a visitor, writes down every hit, and when a pixel fires before consent, it doesn't argue. It brings evidence.

Consent epochs

An epoch is a period with one consent state. A scenario that rejects the banner has two epochs. Tagreeve puts each hit in the epoch where it was sent.

epoch 1 · undecidedhits sent while no answer was given
epoch 2 · deniedhits sent after the visitor rejected
A Google hit is the exception: Tagreeve reads the consent values the hit carries, not the epoch.

Find the evidence

$ grep hit_01M66G9M2S992B5DF1MZ15ZQ08 runs/run_01M66G9DA0714WFS5QHQM5A0NX.jsonl

Search the record file for an ID to see the whole line. Programs can read the file, or the output of tagreeve run --json.

Built-in checks

Built-in checks run on every run. You do not write them.

unknownDestinationFails if a request went to a host that is not your site and that Tagreeve does not know. Allow a host with options.allowUnknownDestination.
sandboxPageUrlFails if a vendor received the address of a sandboxed iframe as the page address. Shopify custom pixels run in such an iframe.
deniedIdentifiersFails if a hit carries an identifier, such as a user ID or a hashed email, while the matching consent signal is denied.
earlyIdentifiersWarns if a hit sent before the first consent answer carries an identifier and its consent signal is unknown.
possibleRealDataFails if the record holds an email, phone number or hash that does not belong to the fake identity.

options.builtins sets a check to warn. The summary then shows WARN for it and the exit code stays 0.

Compare two runs

tagreeve diff compares two record files of the same scenario. It does not open a browser. Use it to see what a change did, for example a new version of your tag manager container.

$ tagreeve diff runs/a/run_A.jsonl runs/b/run_B.jsonl Epoch undecided ga4 page_view added (step "wait-2"): hit_01M66F9D0J8K09EP6VRBY9AYEE count 2 -> 3 (pairing by order)
Epoch / vendor / eventThe group. Hits are grouped by epoch, vendor and event.
step "wait-2"The step that was running when the hit arrived: the wait step at position 2.
count 2 -> 3Run A had two hits in this group, run B three. With different counts the pairing may be wrong, so check by hand.
The diff exits 0 even when the runs differ. The exit code of each run tells you whether its expectations passed.
